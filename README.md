# podtest Invoker

The default Linux x86-64 build is host diagnostics. Phase 2 adds separately tested job parsing, claim delivery policy, a durable journal, and an opt-in JetStream adapter. No build executes jobs; available modes report `execution_ready: false`.

Build with `-Dartifact-control=true` to enable Phase 3's mTLS Claim/refresh/renewal for explicitly assigned runs, verified workspace preparation, restartable artifact uploads and durable `ARTIFACT_CREATED` delivery to Backend. JetStream-to-Claim is exercised only by a separately enabled acceptance fixture; production scheduling, runners and reporting execution results remain disabled. See [artifact upload](docs/artifact-upload.md) for commands, dependencies, and acceptance coverage.

Backend implementation instructions, ownership boundaries, manifest schema, deterministic tar encoding, Claim metadata proposal, hardening limits, and rollout/conformance steps are in [docs/bundle-format.md](docs/bundle-format.md). The manifest and archive are generated by Backend from its normalized immutable revision; authors do not create them.

Build with Zig 0.17.1 and libcurl development headers. Run the host smoke test from the rootless Podman account with its user socket active.

```sh
zig build
zig build test
bash spikes/host-check.sh
PATH=/directory/with/nats-server:$PATH bash spikes/jetstream-check.sh
bash spikes/artifact-check.sh
```

The binary is at `zig-out/bin/podtest-invoker`. `check CONFIG` performs one host preflight. `serve-diagnostics CONFIG` holds the instance lock until shutdown. The JSON fields and defaults are shown in [config.example.json](config.example.json). An empty `podman_socket` uses `$XDG_RUNTIME_DIR/podman/podman.sock`. Provision `state_dir` with mode `0700` before launch. The opt-in JetStream check requires the pinned Zig client dependency and a local `nats-server` executable on PATH. The artifact check requires Go, `openssl` and Python 3 and runs a local CA-signed HTTPS fixture.

The verified compatibility matrix and implementation stages are in [docs/architecture.md](docs/architecture.md). The [control API notes](docs/control-api.md) describe the Go interoperability spike and the draft protocol changes. The deployment instructions are in [docs/deployment.md](docs/deployment.md).
